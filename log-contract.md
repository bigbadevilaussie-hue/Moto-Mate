# Moto-Mate filesystem and log contract — schema 1 LOCKED

2026-11-26. Owner requests a locked contract for every on-device file, 24/7 monitoring, ride logs and multiple legs in a trip. This is the normative design baseline for V1.25 onward, not implemented firmware. Schema 1 is independent of firmware V1.xx. [log-schema-v1.json](log-schema-v1.json) is the exact field offset/type/enum registry and contains deterministic test vectors. A conflict between documents is a release blocker; do not guess. Any change to widths, meanings, IDs, cadence, naming or retention requires explicit contract revision and compatibility tests; additive use of previously reserved values likewise requires review. Existing Bike-Mate data and protocols remain readable via OSA adapters; no change to deployed OSA or protected radio code in this commit.

## 1. Data ownership and cadence

- Monitor is 24/7 coverage, not continuous CPU activity: one qualified observation per ordinary parked wake (300 s actual sleep, <=10 s necessary awake, sleep sooner), plus one monitor observation every 300 s monotonic while already awake riding/maintenance; significant transitions immediately. No duplicate high-rate ride rows in monitor. No fabricated catch-up samples. If sampling is missed, record GAP when feasible. BENCH data separate from FIELD through header flag and OSA routing. No new wake solely to write or upload logs.
- Ride file stores one coherent sample per 5000 ms monotonic while engine-running is confirmed. Also capture leg boundary events. GPS, battery, temperature/humidity, motion validity explicit. Crank/starting evidence uses type 2 monitor samples at 100 ms for up to 5 s when an approved trigger is detected; preserve pre-trigger evidence if acquisition already running, never claim asleep pre-crank capture. Retain donor stall indication (confirmed engine run <60 s), no suppression of short legs. Actual engine detection and acquisition tests are separate field gates.
- Boot, protection/alert, clock corrections, storage faults, missing samples, transfer outcome and wake-budget evidence are typed records in the monitor stream. No separate serial dump, debug file, JSON status file, GPS file, summary file or upload journal. Routine boot event only on cold/reset/abnormal wake or significant state change, not each routine timer wake. FIELD wake summary: at most one per wake and only for a deadline miss, deferred/failed required work, collection or protection event; no summary on an ordinary successful parked wake. BENCH verbose commissioning may emit one per wake. Each adds 48 bytes (capacity below); do not append after final safe boundary. No repeated per-packet events or logging feedback loop from ACKs; aggregate transfer outcomes on next existing write, never rotate solely to report a transfer.
- Summary statistics, date labels, maps, trip/leg aggregation, compression/archive and diagnostic analysis belong on OSA. OSA calculates duration from qualified elapsed measurements; no fixed sample-count times nominal interval when gaps exist. Preserve pre-ride voltage through nearest qualified pre-start capture and leg boundary sample; if missing, null. Existing summary/wire compatibility is an adapter, not a new NVS summary per ride.

## 2. Trip and leg lifecycle

A trip groups multiple confirmed engine-running legs. First confirmed engine start allocates trip_seq and leg 1; emit TRIP_START and LEG_START in monitor, LEG_START also in ride stream. A confirmed stop emits LEG_END (monitor and ride), closes/seals active ride part, but leaves trip open. Restart within a qualified elapsed 120-minute stop window opens next leg under same trip. At >=120 minutes of qualified stopped elapsed time, explicit end, or unqualified continuity after reset/power loss, close old trip (record reason and uncertainty), next start allocates new trip. Timeout evaluated on next ordinary wake/activity; never wake just to close trip. A stall/restart is a new leg if both transitions were confirmed, with stall flag as above; transient unconfirmed state does not split a leg. A trip can cross midnight and contain many legs; no civil-time scheduling, no trip boundary based on calendar day. The 120-minute grouping rule is a technical-lead choice under owner delegation, not a previously specified owner value.

A leg can span many 16 KiB parts; part index begins 1 and increments on rotation, never resets within leg. Rotation does not create a leg. Trip and leg indexes do not wrap; refuse allocation and report fault at overflow. On unclean reboot seal interrupted open file, reconcile durable state and header before new writes, never append to an old boot's unverified tail. If qualified continuity exists, a recovered active leg is marked interrupted and resumed in a new part only when engine evidence supports same leg; otherwise close interrupted leg/trip, create new trip as applicable. Missing duration is unknown, not zero. Host may annotate/group uncertain trips without rewriting device evidence. Lifecycle events are intentionally repeated in monitor/ride; OSA deduplicates same trip/leg/type boundary using identity and event provenance, not file name/date alone. Trip grouping and recovery state must be proven before FIELD.

## 3. Entire LittleFS namespace (allowlist)

All paths are ASCII, flat root, case-sensitive. Only these application file families are allowed. The 32 lower-case hex digits encode generation as 16 hex digits followed by file_seq as 16 hex digits (each numeric big-endian text, zero padded). Example: `/r1_11223344556677880000000000000002.bin`. Generation plus sequence is stable across UTC changes and resets. Device eFuse MAC and generation scope identity on OSA. Prefix m1=monitor, r1=ride, both schema 1. Trip/leg/part in binary header, not long date-based file names. OSA can display meaningful date/trip/leg names from metadata.

| Filename pattern (I = exactly 32 hex characters) | Bytes in basename / full path | Content and lifecycle |
| --- | ---: | --- |
| m1_I.open / r1_I.open | 40 / 41 | Active raw file; not eligible for transfer |
| m1_I.bin / r1_I.bin | 39 / 40 | Immutable valid sealed raw file |
| m1_I.bin.gz / r1_I.bin.gz | 42 / 43 | Optional verified gzip of same raw file; not default until benchmark |
| m1_I.bin.gz.tmp / r1_I.bin.gz.tmp | 46 / 47 | Temporary gzip only; never offered/ACKed |
| m1_I.rec / r1_I.rec | 39 / 40 | Recovered immutable raw bytes, valid header and contiguous good record prefix, damaged/truncated suffix retained; OSA reports gap |
| m1_I.bad / r1_I.bad | 39 / 40 | Quarantined immutable bytes with invalid header or no safe parse; OSA stores exact bytes and marks unparsed |
| .mm-commission-test | 19 / 20 | Historical archived bench-only 8-byte probe 4d4d010500ff55aa; not a production file |

Production filenames never use UTC, whitespace, path separators except leading slash, or variable-length sequence fields. Longest transferable basename 42 ASCII bytes, longest temporary full path 47; buffer >=48 including NUL. No other application-created files, no arbitrary upload filenames, no auto-created directories. Unknown existing files are reported and preserved, not treated as free space or deleted. Legacy donor files are not mounted/transformed as schema 1. OTA images reside in OTA app partitions, not LittleFS; preferences, clock and durable state in NVS; artwork is compiled flash. Serial ring remains bounded RAM only. No standalone zip archives, manifests, trip summaries, duplicate CSVs, or persistent text logs on bike.

## 4. Binary layout

Little endian integers, explicit byte encoding, no native C++ struct padding, floats, locale or native time_t. All numeric units and offsets are in schema registry. Header 80 bytes followed by zero or more 48-byte records; normal seal requires at least one record. Max 339 records (80+339*48=16352 bytes), hard raw cap 16384 bytes. Header CRC covers bytes 0..75, record CRC bytes 0..43, stored unsigned little endian at final 4 bytes; standard CRC-32/ISO-HDLC, check 123456789 -> CBF43926. No per-file footer; size and content digest in transfer metadata. Record identity = (device MAC, generation, file_seq, zero-based record ordinal). Record order is append order, not UTC sort. Header fields match filename; mismatch quarantined. No rewriting header or committed records. Unknown schema/type/reserved nonzero is rejected for interpretation, bytes preserved.

Header: magic MMF1 (4), schema (1), kind (1), header length (2), record length (2), flags (2), device MAC (6), firmware major/minor (1+1), generation (8), file sequence (8), trip sequence (8), leg (4), part (4), opened UTC ms (8), nominal period ms (4), opened boot ID (4), opened monotonic ms (4), reserved (4), CRC (4). Monitor trip/leg/part zero; ride nonzero. Firmware changes or BENCH/FIELD switch seal old active files before further append. Header flag bit0 BENCH; records must match. Header UTC is evidence, not name or schedule.

Record common prefix 20 B: utc_ms u64, boot_id u32, mono_ms u32, type u8, state u8, validity u16. Payload 24 B. CRC 4 B. UTC unknown =0 and quality unknown; current trusted host-synced or qualified holdover only, external RTC quality code reserved until driver is qualified. boot_id diagnostic random token, never unique ID. Monotonic ms is measured since boot, no wrap: saturate at UINT32_MAX and mark timing unusable for subsequent duration arithmetic until next controlled boot; no forced reboot while riding solely for logging. Across boot use independently qualified elapsed evidence, never compare boot-relative ms directly. Saturating counters do not wrap. Invalid sensor fields zero with validity bit clear; legitimate zero with bit set remains valid. Out-of-range/unrepresentable values become invalid, never clamp into apparently valid sample. GPS position valid only with fresh qualified fix; other GPS fields independent. For non-sample records, sensor validity bits zero except operation battery/temp. State activity low nibble, protection bits4..5, BENCH bit6, bit7 zero. Registry defines all enum numeric values.

| Type | Payload (24 bytes; exact offsets in registry) | Stream |
| --- | --- | --- |
| 1 sample | battery mV u16; temp 0.01 C i16; RH 0.01% u16; lat/lon e7 i32 each; speed 0.1 km/h u16; altitude m i16; course 0.1° u16; sats u8; condition flags u8; gravity delta milli-g u16 | both |
| 2 crank_sample | same as sample; 100 ms capture | monitor |
| 3 trip_start / 4 leg_start / 5 leg_end / 6 trip_end | trip u64, leg u32, reason u16, flags u16, elapsed duration ms u64; unknown UINT64_MAX | monitor; leg events additionally ride |
| 7 boot | reset u16, wake u16, prior awake us u32, prior sleep ms u32, lost total u32, flags u32, reserved u32 | monitor |
| 8 clock_sync | prior/new UTC ms u64 each, signed correction ms i64; unknown INT64_MIN | monitor |
| 9 operation | code u16, result u16, battery u16, temp i16, detail code u32, arg0 u32, arg1 u32, reserved u32 | monitor |
| 10 transfer | file seq u64, bytes u32, duration ms u32, result u16, attempts u16, reserved u32 | monitor |
| 11 gap | four u32 lost counts (monitor, ride, crank, events), duration ms u32, reason u16, reserved u16 | monitor or affected ride |
| 12 wake_summary | awake us, planned sleep ms, completed/deferred work masks, min internal heap B, max loop gap us (6 x u32) | monitor |

Operation arguments fixed for v1: protection_change arg0=previous protection enum, arg1=new; storage_fault arg0=cached used bytes, arg1=capacity (UINT32_MAX unknown); sensor_fault arg0=validity bitmask, arg1=failed validity bitmask; button arg0=gesture 0 unknown/1 single/2 double/3 long, arg1=hold ms; maintenance arg0=0 enter/1 exit/2 timeout, arg1=elapsed session ms (UINT32_MAX unknown); ota arg0=expected image bytes, arg1=written bytes; settings arg0=old config_v1 word, arg1=new word; alert arg0=protection enum, arg1=attempt number. detail_code=0 unless a documented stable numeric error is defined by module contract; no raw text or secrets. Result enums in registry. Durations in u32 saturate at UINT32_MAX-1 when UINT32_MAX denotes unknown. For gap counts, zero means no known losses, never proof there were none after power loss. Operation events must not contain credentials.

## 5. IDs and durable metadata, not files

Existing NVS `motomate/config_v1` u32 and `clock/epoch` u32 Unix seconds remain unchanged. New log metadata only: namespace `mmlog`, keys `id_v1` (24 B blob MMI1: magic, generation u64, reserved_through u64, CRC32), `trip_v1` (48 B blob MMT1: registry offsets). NVS key lengths <=15. No per-sample NVS write or per-trip archive in NVS. Allocate generation once during explicit trusted commissioning using a host CSPRNG nonzero 64-bit value, collision-check against OSA's device history; if identity lost do not reuse old generation, never silently format/reprovision. Commit/verify high-water before allocating sequence blocks of 32. Both trips and files use the same monotonically allocated nonzero sequence space (gaps normal). Only retain unused reserved block in RTC with magic/integrity and qualified deep-sleep continuity; cold/software reset skips remainder, allocates next block. Never infer a reusable ID from a missing file; on invalid ID metadata or generation mismatch stop new writes, preserve existing data. Trip metadata committed and read back on trip/leg/part boundary before use; gaps from interrupted allocation normal, no reuse. Recover against headers and lifecycle records, fail closed if ambiguous. RTC retained counters/timers are transient state, not files, checkpoint only on necessary boundaries. Loss accounting across total power loss is best effort, explicitly mark unknown gap; do not promise infinite data retention or a lossless RAM buffer. Daily collection elapsed-time checkpoint implementation remains separate scheduler work; no new arbitrary files or keys without registry revision. NVS erase forbidden on automatic recovery.

## 6. Storage lifecycle and pressure

One filesystem owner; mount without autoformat; no full scan on each sample. Check write length, flush/close and verify safe boundary before sleep; every parked record committed before routine sleep. During ride, bounded buffering at most 4 records/192 bytes or 20 seconds before commit, whichever first; commit transition/critical evidence immediately. This bounds normal volatile loss exposure but not flash failure. Use actual LittleFS error/space/readback tests; Arduino close alone is not evidence of power-loss durability. On short write stop append, retain original bytes, recover good contiguous CRC prefix and rename .rec (or .bad if invalid header/no safe record); never skip corrupt middle and pretend continuity. No in-place repair/truncate; no overwrite on rename. A valid recovered .open may seal as .bin, never resume after uncertain tail. Unknown suffix or unknown file remains preserved. Empty header-only file can be discarded only if validated and proven to contain no record bytes; otherwise preserve. Known stale gzip temp may be removed only while validated raw source or verified final copy exists. Never delete sole copy. Normal rotation: cap 339 records, elapsed 24h collection/explicit collection seal monitor at safe boundary, firmware/profile change, or storage/leg lifecycle boundary. During a ride seal chunk at cap and continue next part; don't wait for trip end to deliver sealed data. No compression or radio during ordinary record commit.

Current physical filesystem 131072 B, measured used 8192 B, free 122880 B; not guaranteed payload capacity. Use measured free allocation (refresh after bounded writes/seal/ACK, not on every sample). At used >=75% flag storage_low and prioritize pending delivery on eligible opportunity; no new wake solely for logs. Reserve 16384 B free for essential protection/transition/gap evidence and LittleFS operational headroom: if free <= reserve, stop routine ride/monitor/crank appends, keep essential events only if safe allocation remains, record loss counters in retained RAM, report gap at first safe write. Never silently discard unACKed files to meet a quota. If essential write fails, report fault via available telemetry/serial; protection and safe sleep still take priority. No automatic formatting; preserve unknown files; no infinite retry or always-awake due to full storage. Thresholds are initial locked engineering choices, require near-full and reset tests. A larger partition is a distinct migration decision, not this change.

Capacity: 288 nominal parked samples/day *48=13824 B +80 header=13904 B, before events/overhead; actual 300s sleep plus awake gives fewer scheduled wakes, not 288 guaranteed. A BENCH diagnostic summary on every wake adds another 13824 B/day at nominal five-minute cadence and extra headers; not the ordinary FIELD cadence. 720 nominal ride samples/hour *48=34560 B plus chunk headers/events. 339 samples span roughly 28 min at 5s (339*5=1695s); one 50-row crank capture 2400 B. Starting free minus one nominal monitor day and reserve leaves ~92592 B, around 2.68 h ride samples before overhead, LESS with wake summaries/crank/events. No promise of multi-day offline/long-trip capacity on this partition. Benchmark radio+gzip and assess larger LittleFS before FIELD; retain dual OTA.

## 7. Compression, transfer and OSA contract

Default on-device raw .bin; stream without whole-file heap allocation. OSA makes gzip archive and exports legacy wake CSV columns epoch,lat,lon,volt,temp,state,flags,sats and ride CSV epoch,lat,lon,volt,temp,state,speed,alt,course (units/scaling as donor). Preserve comments/summary behavior needed by existing GUI via tested adapter, distinguish missing fields, export extra metadata in versioned host representation. Do not silently insert new binary file into old CSV reader or reuse old date-only filename as unique identity. Host UTC date/time and human-readable trip/leg labels are presentation. Legacy archive untouched. OSA keeps device/generation namespace and exact content before ACK. Host filenames for original raw/gzip retain basename; derived trip CSV, summaries and reports are host-owned, not ESP32 files.

Optional ESP gzip only after measured energy/time benefit and compatible transport tests. One RFC1952 gzip member of exact raw bytes, write .bin.gz.tmp alongside raw, close, decode and verify raw size+SHA256, rename to .bin.gz without overwrite, keep raw until verified successor; both names share identity, only one transfer representation chosen per attempt. If compression expands, lacks reserved space, exceeds budget or verification fails, leave raw; clean temporary only under recovery rule. No persistent whole-file RAM. Gzip is lossless, not an alternate record format.

Transfer descriptor: device MAC (12 lowercase hex), generation+file_seq (32 lowercase hex), basename, encoding raw/gzip, transmitted byte length u32, SHA-256 of transmitted bytes (64 lowercase hex), canonical raw length u32 and SHA-256 of canonical raw bytes (same for raw). Recovered/quarantine use raw exact bytes. Header and record CRC are local integrity; SHA-256 binds the transferred representation and canonical identity. OSA stages bytes, verifies descriptor/size/hash and schema or explicit recovery class, fsyncs file, commits without overwrite, fsyncs directory, and makes receipt durable before ACK. Duplicate same identity+canonical hash -> idempotent success; conflict same identity different canonical hash -> reject/no ACK, preserve evidence. ACK binds device MAC, full ID, transmitted size+hash and canonical size+hash, status durable; ESP verifies against currently sealed immutable file before delete, rejects unknown/path/mismatched/stale/partial ACK. No deletion on name-only ACK, HTTP 200, length-only equality, merely queued GitHub push, or BLE notification. Lost ACK retries same identity; exact durable receipt can be returned without duplicating data. OSA handles later GitHub outage, gzip, archiving and notifications; never block device ACK on GitHub. Transfer framing/route and authentication implementation separate protected transport approval/compatibility gate; current donor ACK is name-only and not sufficient for Moto. No production protocol changes here.

Priority: protection first; scheduled collection due after elapsed 24 h, due until batch fully verified; opportunistic on suitable ride/maintenance/normal eligible wake with bounded energy/time, not continuous radio or forced extra wake. Partial batch retains outstanding work. No wait for arbitrary midnight, no OSA-induced wake extension, no long retry loop. Actual transfer pacing and BLE vs Wi-Fi chosen by measurement without altering protected code prematurely.

## 8. Required tests before adoption

Reference vectors in JSON include a ride header, sample with negative temp and latitude, leg end with unknown UTC, standard CRC check. Generator validated widths/offsets and CRC check when registry committed; no firmware/host parser execution or hardware logging test claimed. Add independent C++/Python encode/decode golden vectors, bad CRC/short write/truncation, clock backward/unknown, sequence reservation power-cut, trip multi-leg/stall/midnight/reset/timeout, 339-record rotation, full disk/reserve, gzip corruption/temporary recovery, duplicate equal-size different-content and lost ACK, OSA durable receipt, legacy CSV and summary GUI parity, field energy and no unwanted sleep/radio regression. Verify exact on-device filenames after each test. Current V1.24 mount/status baseline is evidence only, not proof of this contract.
