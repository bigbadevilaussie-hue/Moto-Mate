# Moto-Mate — ESP32 firmware audit and porting TODO

Audit: 2026-11-25. Donor [Bike-Mate V6.49, bc5766c319da25622db1f2c86b58339afd07d5ad](https://github.com/bigbadevilaussie-hue/Bike-Mate/tree/bc5766c319da25622db1f2c86b58339afd07d5ad). Destination V1.00, pre-port. All line references below are to this immutable donor commit, not the future Moto-Mate files.

## Scope and rules

- Read all 32 tracked ESP32 .ino/.cpp/.h files (one sketch, 15 .cpp, 16 headers; approximately 6,685 newline-split entries including blanks). Cross-reference scan for selected suspected dead symbols across all 32 files, stripping comments approximately; manual inspection of their definitions and call sites. No GUI audit, no donor modification, no firmware patch, compile, linker map, hardware test or runtime profiling performed. External libraries and untracked Config.local.h are outside scope.
- Owner has explicitly requested a **cleaned and optimised direct port**, not a blind copy and not a rewrite. Preserve useful functionality/protocols while retiring verified dead code, avoiding duplicate implementations and fixing confirmed faults as each module comes over. This refines the earlier reuse target; 95% is an intent, not a code-line quota.
- Prime Directive: **SAVE THE BATTERY AT ALL COSTS**; collect useful battery/charging evidence without becoming the major drain. Bike-Mate sleep measured on owner's bench PSU: 0.001 A (1 mA) at supply. Match or beat that and measure complete wake-cycle energy.
- **BleManager.cpp/h and proven WifiManager radio sequence remain protected.** Read-only audit findings are not authorisation to change protected files. Discuss a demonstrated issue and agree a narrowly scoped patch before touching these; preserve UUIDs, packets, timings and retries until verified. ESP32 Arduino core **2.0.17 ONLY**. No stack migration. Donor Wi-Fi bring-up currently waits 800 ms after bleStop(), which itself has waits; project rule is at least 500 ms separation, not a reason to shorten proven delay.
- No GUI rewrite. OSA is required. Display rendering is hardware-specific and must change from SSD1306 to ST7735; do not leak the display object's driver API across modules.
- Status labels: **D** = directly demonstrated by source (not necessarily reproduced on hardware); **R** = credible runtime risk, needs reproduction/measurement; **C** = cleanup candidate with no in-tree callers or no meaningful effect, confirm build/link/feature contract; **A** = architectural/owner decision or hardware adaptation. P0 = battery/data integrity/OTA blocker; P1 = correctness/reliability before field use; P2 = efficiency/maintainability; P3 = cosmetic. Every checkbox starts open. A source finding is not proof of an observed field failure.

## 1. P0 — first fix the battery and data-loss traps

WakeLogger.cpp:391–412 intentionally leaves a .sealed file if gzip fails; DriveUpload.cpp:110–163 can recover it. Boot therefore deletes the only raw copy before reconciliation. ## 6. Suggested port sequence — one tested subsystem at a time

1. **Before code:** confirm hardware audit blockers, GPIO/power/wake design, S3 board/partition config and test compile with core 2.0.17. Capture donor functional baseline/boot logs where available; create golden CSV, binary summary layout and BLE/HTTP fixture tests before touching contracts. Decide OSA identity/coexistence. No speculative rewrite.
2. **Power and sensor foundation:** Config, safe output ownership, timer/button wake, calibrated ADC, SHT40/MPU, GPS, active buzzer, minimal TFT. Prove idle sleep <=1 mA at 12 V input (owner's Bike-Mate PSU baseline), no rail leak, wake energy and held button.
3. **Clock and storage:** remove dead manual counter, preserve clock sync interfaces; fix destructive recovery, transactional gzip, safe filenames, mount policy, sample states. Simulate reset and full storage. Port ride lifecycle and capture with validated transition table.
4. **BLE/OSA and upload:** copy protected BLE initially, verify telemetry/clock/ACK/packet behavior and actual OSA reception on S3. Decide targeted fixes for backlog/ACK/name mismatches with owner; preserve 4 AM, manual and automatic delivery without redundant long wake. Never change transport on theory.
5. **Maintenance/OTA and alerts:** preserve Wi-Fi bring-up; test bounded maintenance and real HTTP OTA. Decide legacy URL OTA, direct SMTP fallback and /acc override. Test missing server, stalled link, invalid settings and no unintended drain.
6. **Final cleanup and acceptance:** remove confirmed unused symbols/APIs as their module ports, re-run all tests, inspect compile warnings/link map, compare flash/RAM/free heap, awake duration, measured current/energy and log fidelity. No arbitrary code-line reduction target. Keep code small and readable but protect diagnostics and proven behavior. Field install only after bench passes; seven-day test and reliable starting reserve.
