# V1.08 B2 USB sleep commissioning

Dedicated bare USB S3 test; no Wi-Fi, TFT, external GPIO, filesystem or sensors initialised. Three BLE wakes: cold boot, timer wake after 300 s, timer wake after 300 s. Then terminal deep sleep with no wake source; physical RESET or BOOT+RESET for recovery/reflash. No battery/vehicle installation yet. Each wake starts BLE immediately, one challenge/clock session; stop at 7 s boot-monotonic deadline to leave teardown margin under 10 s. SDK calls synchronous, hard deadline not guaranteed; actual measured pre-sleep time retained in RTC memory and read by OSA on next wake. If no host, still sleep; no fake PASS. Timer arm failure stops in bench (reset required). Actual sleep current must be measured separately; USB CDC disappears in deep sleep and serial may miss early logs.

B2 name Moto-Mate-B2, service 0da80001-7d91-4a75-9a7c-56d1f29b0731, identity/challenge/clock same B1 semantics using 0da80002/3/4. Identity MMB2/1.08/<8 hex random boot ID>. Metrics READ 0da80005 with five uint32 LE: retained run ID, wake sequence (1-3), previous pre-sleep awake microseconds, previous flags (1=local challenge+clock and shutdown pass, 2=shutdown verified, 4=under 10s), esp_sleep_get_wakeup_cause (timer=4). Previous metrics zero on wake 1; separate boot ID per wake, same run ID. Read current clock before correction; epoch quantisation limits drift precision. OSA V1.41 /moto/sleep/start arms bounded collection of three wakes without occupying BLE worker between wakes. Host requires sequential wakes, same run, distinct boot IDs and timer cause, verifies prior wake flags and records monotonic interval. Two completed pre-sleep durations visible remotely, third serial only. Sleep interval is programmed 300s, not proven accurate until measured. No production radio or GPIO policy change. V1.07 diagnostic baseline retained in git.
